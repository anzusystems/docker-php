2026-09-16
===

### Added
- `config/all-8.5/usr/local/etc/php/php.ini` - PHP 8.5 images were built without any `php.ini`
- `config/fpm-8.5/usr/local/etc/php-fpm.conf` and `config/fpm-8.5/usr/local/etc/php-fpm.d/www.conf` - PHP 8.5 fpm image was built without any php-fpm configuration
- [doc/configuration.md](../configuration.md) - every environment variable, the directive it sets and its default
- Environment variables for the directives that were still hardcoded in `php.ini` and `www.conf`. All defaults keep the
  value the images used so far, so nothing changes unless you override them:
  `PHP_CURL_CAINFO`, `PHP_MAX_INPUT_VARS`, `PHP_MAX_MEMORY_LIMIT`, `PHP_OPCACHE_JIT_BUFFER_SIZE`,
  `PHP_OPENSSL_CAFILE`, `PHP_OPENSSL_CAPATH`, `PHP_PM_MAX_CHILDREN`, `PHP_PM_MAX_REQUESTS`,
  `PHP_PM_MAX_SPARE_SERVERS`, `PHP_PM_MAX_SPAWN_RATE`, `PHP_PM_MIN_SPARE_SERVERS`, `PHP_PM_START_SERVERS`,
  `PHP_REGISTER_ARGC_ARGV`, `PHP_SESSION_COOKIE_PARTITIONED`, `PHP_ZEND_MAX_ALLOWED_STACK_SIZE`
- `DOCKER_APP_EXCLUDED_ENV_VARS` env - vars excluded from the `/etc/environment.app` export (regex alternation), default `HOME|LOGNAME|OLDPWD|PWD|SHELL|SHLVL|TERM`
- `/etc/environment.app` export in `config/all/usr/local/bin/docker-entrypoint` and `config/fpm-nginx/usr/local/bin/docker-entrypoint`, so cron jobs run with the application environment
- `SUPERVISOR_MESSENGER_OPTIONS`, `SUPERVISOR_MESSENGER_STARTSECS`, `SUPERVISOR_MESSENGER_STARTRETRIES` and `SUPERVISOR_USER` support in `config/all/usr/local/bin/generate-messenger-supervisor-conf`

### Changed
- PHP 8.4 `8.4.21` -> `8.4.25`
- PHP 8.5 `8.5.6` -> `8.5.10`
- Pecl ext mongodb `2.3.3` -> `2.5.2`
- Pecl ext xdebug `3.5.1` -> `3.5.3`
- Nginx `1.30.2` -> `1.30.4`
- Composer `2.9.8` -> `2.10.3`
- FFmpeg `7.1.4` -> `7.1.5`
- Libvips `8.18.2` -> `8.18.6`
- `php.ini` and `www.conf` no longer ignore the `PHP_*` envs the Dockerfile declares, which changes the effective values of:
  - `upload_max_filesize` `2M` -> `20M` (`PHP_UPLOAD_MAX_FILESIZE`)
  - `opcache.memory_consumption` `128` -> `256` (`PHP_OPCACHE_MEMORY_CONSUMPTION`)
  - `opcache.interned_strings_buffer` `8` -> `32` (`PHP_OPCACHE_INTERNED_STRINGS_BUFFER`)
  - `opcache.max_accelerated_files` `10000` -> `32531` (`PHP_OPCACHE_MAX_ACCELERATED_FILES`)
  - `opcache.error_log` unset -> `PHP_OPCACHE_ERROR_LOG`
  - every other directive keeps its previous value, it is only read from its env now
- `PHP_OPCACHE_VALIDATE_TIMESTAMPS` default `0` -> `1` - it was declared but no config file ever read it, so opcache
  was running with `1` anyway. Kept at `1` so the images still pick up code changes; set it to `0` for production-like runs
- `config/all/usr/local/bin/cron-cmd` sources `/etc/environment.app`, picks the run environment from `APP_DEPLOY_ENV` with `DEPLOY_ENV` fallback and logs why a command was skipped
- `config/all/usr/local/bin/start-messenger` passes unknown options through to `messenger:consume` instead of failing
- Default `SUPERVISOR_MESSENGER_NUMPROCS` `2` -> `1`

### Removed
- `config/all-8.3/` and `config/fpm-8.3/` - leftovers after the PHP 8.3 variant was dropped in `5.0.0`
